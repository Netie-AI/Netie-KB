## Expected vs actual

**Expected:** two lanes that each pass their full suite plus an adversarial verifier compose into a working path.

**Actual:** Cortex accepted only bare table names; DMS sent `bronze.<t>`. Every question on a SQL-source Space got `422 caller_ontology_invalid:bad_identifier`, so generation was never reached. Each lane tested against a fake of the other (DMS fake Cortex never parsed the ontology; Cortex tests sent bare names). A second mismatch appeared the same way in round 2: DMS sent only question-named columns, Cortex treated them as the column allowlist, so legitimate group-bys refused.

## Reproduction

1. Start Cortex (insights-onto 28c48c9e) and DMS (space-gen 4ed78be) on loopback with a stub OpenVault/model.
2. Ingest two Postgres tables into a non-demo Space; POST /v1/chat/ask "How many schools are in Alameda county?".
3. Tap Cortex: /v1/insights returns 422 bad_identifier; envelope ABSTAIN, no generation.

## Root cause class

Contract-by-mock: a cross-repo boundary with no shared fixture. Each side's test double encoded its own assumption about the wire shape, so both suites certified incompatible halves.

## Invariant gap

"Assert the artifact the customer receives" and "adversary != verifier" held per lane, yet missed it. Missing rule: a change that crosses the DMS-Cortex HTTP boundary must include one loopback proof over real HTTP (both services from the changed trees, stub only the model) asserting the DMS envelope. Fix landed with one shared naming rule (exact schema.table, source field) and the proof passed 9/9 (dms#311 76aa7bc, Cortex#277 75c9ba85).

## Notes

Same run also showed word-based SQL gates hit a ceiling after 4 verifier rounds; scope-based analysis (sqlglot traverse_scope, fail closed) closed the CTE bypass class in one round.
