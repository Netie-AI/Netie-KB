## Expected vs actual

Expected: `pytest tests` on a fresh venv either skips control-plane honestly
or fails with one named reason; `cortex-contract` installs from the pin.

Actual: a block of pytest `E` at the start of the run (then many passing
dots) when Postgres is down and `DMS_SKIP_CONTROL_PLANE_TESTS` is unset.
Agents then hunt `cortex-contract` on PyPI (it is not published), pass
`--timeout=300` (pytest-timeout is not a dep), and redirect logs to
`$TMPDIR/pytest_full.txt` which Git Bash resolves to `/pytest_full.txt`.

## Reproduction

1. Docker Desktop stopped. No Postgres on 127.0.0.1:5432.
2. `E:\DMS\.venv\Scripts\python.exe -m pytest tests -q` with no skip env.
3. First ~29 results are `E` from `tests/control_plane/conftest.py`
   AssertionError, not collection/import errors.
4. Same command with `DMS_SKIP_CONTROL_PLANE_TESTS=1` prints `s` for those
   29 and continues. That is what GitHub CI already does.

Wheel: `E:\Cortex\packages\cortex_contract\dist\cortex_contract-1.2.0-py3-none-any.whl`.
`D:\Cortex` does not exist on this laptop; `ci_local.sh` still defaults there.

## Root cause class

Environment-default mismatch, not a product regression. Control-plane
fail-closed (R-0002) is correct; the agent treated fixture errors as
suite-wide breakage and then compounded with invalid pytest flags and a
Unix-root redirect. A second Windows-only class: two pytest processes
locking `data\dms_demo.duckdb` (CI Ubuntu does not hit this).

## Invariant gap

R-0002 held (skip must be explicit). Missing operational rule: local
bootstrap commands for this machine (wheel path, skip env, Windows log
path). Promoted into DMS `.cursor/rules/local-test-bootstrap.mdc`.
F42 / EPIC-018 CI-ACCURACY is still the product gap (oracle CLI not in CI).
