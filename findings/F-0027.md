## Expected vs actual

**Expected:** a claim "DMS is better than DB-GPT" rests on one benchmark, one LLM, one grader, with n and a rule-of-three bound.

**Actual:** no such number exists. DB-GPT-Hub's README baseline (update 2023/12/08) is Spider execution accuracy (EX) per fine-tuned model, e.g. CodeLlama-13B-Instruct lora all=0.746, CodeLlama-7B-Instruct lora all=0.702, base CodeLlama-7B all=0.539. DMS has `scripts/score_bird.py --minidev ... --live` (A1-02, dms#264) grading `/v1/chat/ask` envelopes against BIRD Mini-Dev gold SQL, but no live Mini-Dev run is recorded on dms main 0577275. Different datasets (Spider vs BIRD) and different metric shape (DB-GPT answers every question; DMS abstains) make any cross-quote meaningless.

## Reproduction

1. Read DB-GPT-Hub README "Baseline" table: metric is Spider EX, no BIRD row.
2. `git grep -i "mini-dev\|minidev" origin/main -- CHANGELOG.md STATUS.md` on dms: harness and self-check only, no measured n.
3. Cortex dms#231 Phase 1b (relayed): generate_sql adds no accuracy over ontology ranking; 15 oracle-wrong answers carried L2_VALIDATED.

## Root cause class

Benchmark-mismatch: a competitor bar quoted on dataset A while the product is instrumented on dataset B, plus a confidence badge that is not bound to row correctness (L2 on wrong grain). Either alone makes "better than" unfalsifiable.

## Invariant gap

"Assert the artifact the customer receives" and "Don't claim 0 wrong below n=300" cover the scoring side. Missing rule: a comparative claim must run both systems on the same questions, same LLM, same grader, and report EX-on-all (abstain counted as miss) beside precision-on-answered.
