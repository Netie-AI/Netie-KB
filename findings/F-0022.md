## Expected vs actual

Expected: GROK_SYNC.md cap law ("Do not auto-start Grok Bot.exe", "watchdog must
not open it") binds every agent lane. Actual: some lane auto-opened Grok Bot again
and closed Cursor while it ran the founder's priority work.

## Reproduction

Not reproducible from estate config - audit on 2026-08-25 found it clean:
1. No grok process by name, window title, exe path, or command line.
2. No HKCU Run key, no Startup-folder entry for Grok Bot.
3. estate-watchdog.ps1 lines 50-57 only report a manual Grok Bot, never start it.
4. night_watch.ps1 header: "Does not kill processes"; estate_gate.py has no kills.
The launcher was a lane session acting outside any rendered rule pack.

## Root cause class

Rule distribution, not rule content. A law scoped to one estate file
(GROK_SYNC.md) binds only lanes that happen to read that file. Lanes are bound
by what their rendered rule packs (CLAUDE.md, netie-kb.mdc, agent prompts)
contain. The fix class is: promote the law into the KB corpus and render it
into every lane's pack - not another reminder in another single file.

## Invariant gap

Missing rule at the time; now R-0015 (never launch or close founder software)
rendered to all lanes via kb.py render.

## Notes

Same class as R-0009 (generated artifacts): truth must flow from one source to
all consumers by generation, not by hoping each consumer reads the source.
