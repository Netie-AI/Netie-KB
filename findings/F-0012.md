## Expected vs actual

**Expected:** a manifest-grounding gate refuses a question whose answer would read
a table the session never bound. It shipped with tests, and the suite was green.

**Actual:** on the product path it could not refuse anything. `answer()` accepted
`verified: VerifiedManifest | None = None`, and when the argument was omitted it
minted a *self-issued* grant whose tables were every table the semantic pack
declares. The gate then intersected the SQL's tables against that grant. Both
sides came from the same place, so the intersection was never empty.

A question about an uploaded spreadsheet was answered from the synthetic demo
warehouse, badged `governed_metric`:

    POST /dms/query  "total revenue in my uploaded file"
      -> 200, badge governed_metric, rows [{"revenue_myr": 80375993.99}]

The gate was not weak. It was an identity comparison wearing a security control's
name, and it read green permanently.

## Reproduction

    PACK=dms python -c "
    from fastapi.testclient import TestClient
    from CortexOS.api.app import create_app
    c = TestClient(create_app())
    print(c.post('/dms/query', json={'question':'total revenue in my uploaded file',
                                     'session_id':'demo-unbound'}).json())"

Note the session is deliberately **unbound**. Binding a narrow manifest makes the
gate work, which is why every test written for it passed.

## Root cause class

**A check whose two operands share a producer.** Not "the manifest check was
incomplete" - the check was correct. The defect is that nothing guaranteed the
grant came from outside the component being checked. When a component can supply
its own authorisation, authorisation is not a constraint on it.

Generalised test: for any check `A subset-of B`, ask **who produces B**. If the
answer is "the same code path that produces A, when the real source is absent",
the check cannot fail and its green is uninformative.

Three sibling shapes found in the same pass, same underlying error of trusting a
gate nobody watched fail:

1. **A clause ended negatively.** Exclusion parsing decided where an entity
   clause stopped by popping words on a stop-list. The named root-cause class was
   "two lists can disagree"; the fix made the lists agree *today*, so any word
   neither list knew (`also`, `just`, `kindly`) reopened it. Ending the clause
   **positively**, at what actually resolves, removes the ability to disagree.
   A fix that enumerates cannot close a defect whose class is "the enumeration is
   incomplete" (R-0004).

2. **A deliberate defect left in the tree.** `bench/corpus.py` carried three
   `# REVERT-A` lines short-circuiting its own fix back to the code it replaced -
   the reintroduced defect from an R-0007 proof, never restored. The tests for the
   fix existed and were red; the fix behind them was disabled. The proof and the
   restore are two steps and only one of them is interesting.

3. **An exemption that swallowed the target.** A README-claim gate skipped any
   sentence containing a negation, so honest disclaimers would not trip it. The
   one unbacked claim on the front page denied one control while asserting another
   in the same breath - "X is **not** shipped, code runs in Y" - and so was
   invisible. Splitting at dashes and semicolons still passed; only splitting at
   **commas** made it fire.

## Invariant gap

**R-0007** should have caught all four: a gate must be proved able to fail before
it is trusted green. None of these four had been watched failing. In each case the
authors wrote tests that passed and stopped there.

R-0007 currently reads as advice about *commands* that cannot fail
(`python -m importlinter.cli`, and now `pytest --timeout=N` without
`pytest-timeout`, which errors on the argument and still exits 0). It should
extend to *assertions*: an assertion nobody has watched go red is not evidence,
and the cheapest way to watch is to neutralise the fix and re-run.

**R-0003** is what surfaced this. Verifiers were prompted to *refute* rather than
confirm and told to default to FAIL when uncertain; each claimed gap then went to
a second adjudicator to catch false FAILs (R-0005 in the other direction). Six of
seven tickets reopened, and every refutation held. Confirm-shaped verification
would have closed all seven.

## Notes

- **A fix can replace one unbacked claim with another.** The Wasm sandboxing claim
  was correctly deleted, and the sentence that replaced it asserted "untrusted
  code is packaged and run in containers" - equally false, since the runner
  returns `unsupported_stack:docker`. Verify replacement text as adversarially as
  the text it replaced.
- **A corpus can cover half a commit.** `ebd049b` fixed a follow-up path and a
  single-question path. Reintroducing the follow-up half turned the gate red
  (`wrong=6`); the single-question half left it green, because every seed in that
  category replays turns. Coverage is per *shape*, not per commit or per ticket.
- **Agents that die still mutate the tree.** Nine subagents hit a session limit
  and all reported failure, having already written 221 insertions, two test files
  and 26 deletions. Treat a failed run as possibly having changed the working
  tree: check syntax, conflict markers, and whether deletions match intent.
- **Escaping hazard, cost about 20 minutes.** Writing a Python patch script inside
  a shell heredoc turned `\b` in a regex into a literal backspace byte (0x08).
  The file parsed, the regex compiled, and it silently never matched - so a split
  returned the whole string and a multi-SKU exclusion applied only its first term.
  Repairing it with `raw.replace(b"\x08", b"\\b")` failed for the same reason;
  `bytes([92, 98])` worked. Prefer the editor tools over heredoc patch scripts for
  anything containing backslash escapes.
