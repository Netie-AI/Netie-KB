## Expected vs actual

**Expected:** one orchestration layer (Cortex), one vault (OpenVault), Control as the operator page that shows who is doing what. Laptop control via already-armed UACC + Playwright (S-0002). Skills land in Netie-KB (S-0003) so the next outreach or similar task pulls a registry skill instead of re-deriving.

**Actual (the request as spoken):** Control would bypass OS permission, auto-provide every credential, spawn and kill PRD/Epic/Ticket agents, and become the chest of tickets and tools. That is three products in one shell: a second vault, a third orchestrator, and a skill registry fork.

**What held:** `/v1/secrets` and `/v1/run` stay 405. UACC `get_system_info` and Playwright `browser_tabs` worked in this Cursor session without a second mouse stack. Control gained display-only Crew `/crew/health` and KB `/healthz` so a 1000-executor fleet can see arming and the skill chest without Control owning either.

## Reproduction

1. Ask Control to auto-sign-in with OpenVault credentials or to spawn Ticket/Epic/PRD agents.
2. GET `http://127.0.0.1:8040/v1/secrets` and `/v1/run`.
3. Both answer 405 with owner OpenVault / Cortex.

## Root cause class

Plane collapse. A scale need (everyone must know who is doing what) was phrased as Control growing the organs of planes 2 and 3.

## Invariant gap

NETIE.md section 3 already forbids this. S-0001 already names RUNTIME + CLAIMS + Crew health as the fleet loop. F-0025 already says claim the ticket before a second lane starts. The gap is operator-facing: the page did not show Crew health or the KB chest, so the request looked like missing product rather than missing display.
