## Expected vs actual

**Expected:** running `python -m pytest` inside a git worktree imports that worktree's
`tests` package.

**Actual:** `D:\Cortex` is on `sys.path` through an editable install, and the branch
checked out there tracks `tests/__init__.py`. A regular package beats a namespace
package regardless of path order, so `import tests.test_crew.conftest` resolved to the
other lane's tree while every other import came from the worktree. Test helpers
(`FakeLLM`, `FakeBridge`, `wait_run_done`) were silently taken from a different commit.

## Reproduction

1. From the worktree: `python -c "import tests; print(tests.__file__)"` -> the sibling
   checkout's `tests\__init__.py`.
2. `pytest` from the worktree still collects worktree test files, so the split is
   invisible until a helper differs between the trees.

## Root cause class

Package resolution silently crossing checkouts: a namespace package in the worktree loses
to a regular package elsewhere on `sys.path`.

## Invariant gap

Missing rule. Candidate: a worktree test run pins its own `tests` package (a shim whose
`__path__` points at the worktree) or asserts `tests.__file__` before trusting a local
run. CI is unaffected, so this only ever misleads local verification - including a
mutation run, where a mutant could be "killed" by another tree's code.

## Notes

Fix used: a scratch shim directory on `PYTHONPATH` whose `tests/__init__.py` sets
`__path__` to the worktree's tests. Also affects any agent asked to reproduce a local
count in a worktree.
