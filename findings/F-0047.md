## Expected vs actual

**Expected:** The unit suite never imports pyodbc. SQLSRC-06 predicted the live
container's self-signed cert is refused by the safe default.

**Actual:** `SourceConfig(..., encrypt=True, trust_server_certificate=False)` raised
`SourceConnectionError: could not connect to sqlserver://127.0.0.1:1433/sales`.
Cause: ODBC Driver 18 `SSL Provider: The certificate chain was issued by an
authority that is not trusted` (08001). The same config with
`trust_server_certificate=True` connected. #112 exposing the field on the POST body
is the right knob; the default stays safe for Azure SQL.

## Reproduction

```
SourceConfig(kind="sqlserver", host="127.0.0.1", database="sales",
             user="dms_reader", password=..., encrypt=True,
             trust_server_certificate=False)
connect(cfg)  # SourceConnectionError, ODBC 08001 untrusted cert
```

## Root cause class

**Driver TLS reality the fake DB-API cannot simulate.** pyodbc talks to
msodbcsql18; the fake cursor never presents a certificate.

## Invariant gap

Not a product bug. The live request MUST set `trust_server_certificate: true` for
a local container and MUST NOT for a customer database (SQLSRC-06). Compose
`apps/api/Dockerfile` still has no ODBC driver; this run used a host uvicorn on
:8091, not the compose image.
