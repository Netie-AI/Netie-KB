## Expected vs actual

**Expected:** a repo that had history an hour ago still has it, and `git symbolic-ref HEAD`
writes HEAD.

**Actual - two failures in one afternoon, on the meta repo `D:/Netie`:**

1. `.git` was found to contain only a fresh `git init`: `HEAD -> refs/heads/master`, empty
   `objects/` and `refs/`, a 130-byte `config` with no remote, every file dated 2026-08-28
   18:02. The working tree was intact, and an agent had read history from and pushed to
   this same directory earlier the same session. It presented as total history loss. It was
   not: every commit was on `Netie-AI/Netie`, and the working tree still held every file.
2. After reattaching (`git remote add` + `git fetch` + `git reset --mixed origin/<branch>`),
   both `git symbolic-ref HEAD refs/heads/<branch>` and `git branch -m` failed with
   `error: couldn't set 'HEAD'`, leaving HEAD pointing at a ref that had just been renamed
   away - an unborn branch. `touch .git/HEAD` succeeded. Eleven Cursor processes were
   running.

The second failure is a Windows editor holding `.git/HEAD` open. git writes HEAD by writing
`HEAD.lock` and renaming it over `HEAD`; Windows refuses to rename over an open handle. A
plain write (`touch`) does not rename and succeeds. That asymmetry IS the diagnostic:
`touch` OK plus `symbolic-ref` fails means something holds the file, not a permission.

## Reproduction

1. Open the repo in Cursor (or VS Code) with git integration on. Leave it open.
2. From a terminal: `git symbolic-ref HEAD refs/heads/some-branch` -> `couldn't set 'HEAD'`.
3. `touch .git/HEAD` -> succeeds. Confirms the hold, not a permission.
4. For failure 1 the exact trigger was not identified. A snapshot-restore tool, or an init
   script re-run over an existing `.git`, are both consistent with every file in `.git`
   carrying one old mtime while the working tree carried new ones.

## Root cause class

**Unowned writes to shared mutable state.** `.git` is one directory touched by two agent
lanes, an editor's file watcher, and whatever re-initialised it - none of which owns it and
none of which announces a write. F-0019 is this class on the working tree (a checkout);
F-0025 is this class on the ticket queue (a pickup); this is the same class on the git
directory itself. Fixing any one symptom leaves the class.

## Invariant gap

R-0006 forbids `git add -A` and unguarded amends. R-0015 forbids closing the founder's
editor. Neither detects a repo whose HEAD does not resolve or whose remote is gone.

**Candidate, cheap, concrete:** `Internal/Agents/estate_gate.py` already walks every estate
repo. Add `REPO_DETACHED`: fail if `git symbolic-ref -q HEAD` does not resolve to an
existing ref, or `git remote get-url origin` fails. Two subprocess calls; both would have
gone red within one heartbeat of either failure.

## Notes

**Recovery recipe, non-destructive, verified on the working tree that mattered:**

```
git remote add origin <url>                 # errors harmlessly if present
git fetch origin
git reset --mixed origin/<branch>           # index + HEAD ref only; never touches files
git symbolic-ref HEAD refs/heads/<branch>   # fails while an editor holds HEAD - see below
git ls-files --deleted                      # restore ONLY these, one by one, if wanted
```

Never `git add -A` afterward: the tree carries other lanes' uncommitted files and untracked
vendor dirs (14,703 untracked here). Stage explicit paths.

**On the HEAD hold.** The agent may not close Cursor (R-0015), and the auto-mode classifier
correctly blocks a direct write into `.git/HEAD` as a git-internals write. So this is a
human step: the founder closes the repo's Cursor window or its git panel, then anyone runs
the `symbolic-ref`. Say so plainly rather than retrying - the third retry today was the one
that left HEAD dangling.

**Which branch to reattach to.** The parallel lane's recipe said `origin/main`. The working
tree's content decides: when `git diff --stat` against the candidate shows a 400-line PRD
diff where 40 is expected, that is the wrong branch. Reattach to the branch the files came
from, not the default.
