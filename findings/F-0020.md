## Expected vs actual

Expected: a Cortex manifest refusal (PathNotAllowed / StatementNotAllowed /
SqlNotAnalyzable - nothing read, no SQL) reaches the DMS customer envelope from
POST /v1/chat/ask as abstained=true, badge ABSTAIN, text naming the refusal.

Actual: the envelope says badge L2_VALIDATED ("This SQL was generated, then
checked"), abstained=false, over prose that says nothing was read - and
assert_envelope_valid (E1-E9) passes.

## Reproduction

    python D:\DMS\scripts\repro_refused_badge.py     # exit 0 = defect present

from the normalised badge.

## Root cause class

An enum lookup whose default is the CONFIDENT member. DMS fixed the same class
on its own side (normalize_badge: unknown -> ABSTAIN, PRD-001 F33 (2)); the
engine still had it one hop upstream, so by the time DMS looked, the badge was
a known legitimate one. Fix is the class (unknown -> least-confident outcome)
plus the word ("refused" is an abstain signal), not a DMS special case for
layer == "refused". Same family as F38's rule: the default branch of a
classifier must be the least-attributive outcome available.

## Invariant gap

R-0001 (assert the artifact the customer receives) was honoured - and still did
not catch it, because every envelope assertion checks internal consistency.
E9 needs an unbacked number (the refusal text has none); the hard-rule-12 net
needs sql_used (None). Missing rule candidate: an abstention or refusal at any
hop must survive to the customer as abstained=true - "a refusal is also an
artifact the customer receives" - enforced by a test that feeds the unfixed
engine's own refusal dict through the whole chain (the repro script is that
test once the fix lands; R-0007 says it must be shown red first).
