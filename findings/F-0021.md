## Expected vs actual

The DMS demo router is supposed to refuse predictive questions: the demo warehouse
holds historical transactions only and has no forecast model, so any figure for a
future period is a guess. A guard existed and was believed to cover this.

Expected: a forecast question abstains.
Actual, reproduced on main at 7b8db1b:

    "project total sales for the coming year"      -> L2_VALIDATED  RM 25,654.50
    "how much revenue do you expect us to make"    -> L2_VALIDATED  RM 25,654.50
    "what is the outlook for year-end revenue"     -> L2_VALIDATED  RM 25,654.50
    "estimate warehouse capacity utilisation
     for next year"                                -> L2_VALIDATED  97.8%

All four with abstained=false. Each is a real historical number, correctly computed,
answering a question nobody asked - wearing a confident badge.

## Reproduction

    cd D:\DMS && git checkout 7b8db1b
    python -c "import os,tempfile,pathlib; d=tempfile.mkdtemp(); p=pathlib.Path(d)/'dms_demo.duckdb'; os.environ['DMS_WAREHOUSE_DB']=str(p); from dms_executor.demo_warehouse import ensure_demo_warehouse; ensure_demo_warehouse(p); from dms_executor.demo_ask import answer_demo_question; print(answer_demo_question('what is the outlook for year-end revenue')['badge'])"

Prints L2_VALIDATED.

## Root cause class

Not "the regex was missing a word". The class is: **a literal list standing in for a
class of intent**. The guard was

    \b(forecast|predict|projection|what if|hypothetical|next quarter)\b

"projection" was present but "project" was not. "next quarter" was present but
"coming year" was not. The list enumerates *tokens someone thought of*, and every
phrasing outside it falls through to the answering path, not to the refusing path.

The failure is asymmetric and that is what makes it dangerous. A guard that
over-matches produces a visible refusal somebody complains about. A guard that
under-matches produces a plausible number with a green badge that nobody
complains about, because it looks right. The default direction of a missed match
must be refuse, not answer.

Same shape as A-0005 and A-0007 in this corpus: a control that is a list rather
than a property of the input, positioned so that "not on the list" means "allowed".

## Invariant gap

Missing rule. Closest existing:

- R-0011 (a silent fallback is a lie) is adjacent but not the same - nothing here
  was degraded, the wrong answer was fully computed.
- R-0005 (a control that refuses legitimate work is a failure) is the *opposite*
  direction and if applied alone pushes a guard toward under-matching.

Proposed rule: **a refusal gate keyed on a list of literals must state its
false-negative bound, or be rewritten as a property of the input.** If neither is
possible, the unmatched case defaults to refuse.

The measurement rule R-0010 applies to the guard too: the fixed guard here is
still a heuristic over English phrasing with **no measured bound** on what it
misses. It closes four reproduced holes and the class around them. It does not
close the category, and PR #67 says so rather than claiming coverage.
