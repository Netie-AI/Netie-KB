## Expected vs actual

**Expected:** a quoted heredoc - `python - <<'PY' ... PY` - delivers its bytes to Python
verbatim. Bash performs no expansion inside a quoted heredoc, by definition.

**Actual, three shapes of the same defect, all inside the Claude Code Bash tool on Windows:**

1. A doubled backslash arrived as a single one. `"D:\\Netie"` reached Python as `D:\Netie`
   and raised `SyntaxError: malformed \N character escape`.
2. An anchor string containing `f"\\n_probe = \\"..."` reached Python with the escapes
   already collapsed, so `s.count(anchor)` was 0 on a file the agent had written minutes
   earlier. Five times, over three turns, each misread as "the file changed underneath me".
3. A body containing markdown code spans died before Python ever ran:
   `/usr/bin/bash: eval: line 61: syntax error near unexpected token '92'` - the token being
   the inside of a backtick span. The tool wraps the command in `eval`, and `eval` performs
   command substitution on backticks and processes backslashes across the WHOLE string,
   heredoc body included, before bash gets to see a heredoc at all.

`MSYS_NO_PATHCONV=1` was set for the later attempts and changed nothing. This is not MSYS
argument conversion; it is the transport re-evaluating the command text.

## Reproduction

Three lines. If the printed length is 2 rather than 3, the transport collapsed the pair:

```
python - <<'PY'
print(len("a\\b"))
PY
```

And any heredoc whose body contains a backtick will fail in `eval` before Python runs, with
a message naming a token from inside the span rather than the span itself.

## Root cause class

**A transport that edits what it carries.** The heredoc promised verbatim delivery and the
layer between the tool and the shell re-evaluated the body on the way through. This is
R-0009 inverted: a generated artifact must not be hand-edited, and a hand-authored one must
not be machine-edited in transit. An intermediary that rewrites content is a defect in the
intermediary, not in the content - and it is a particularly expensive one because every
symptom points at the file.

## Invariant gap

No rule. **Candidate rule:** file content never goes through the Bash tool. It goes through
the Write tool, which passes bytes verbatim; a bash command then carries paths only - `cp`,
`mv`, `test -s` - and paths use forward slashes, which Windows accepts everywhere that
matters. Python embedded in bash contains no backslash, no backtick, no `$`, and builds a
backslash with `chr(92)` if it must have one.

The diagnostic that would have saved three turns: **anchor count 0 on text you just wrote
means suspect the transport before the file.** Print `repr()` of the anchor from inside the
heredoc first. If it does not match what was typed, the file was never the problem.

## Notes

Two more habits, learned the same afternoon and stated once:

- **A heredoc is the last link in any `&&` chain.** The terminator ends the chain; the next
  line runs unconditionally. A validate-and-commit line placed after a heredoc committed an
  EMPTY registry template because the fill step inside the heredoc had failed silently.
- **Gate a commit on an explicit test of the artifact**, never on the exit code of a line
  that ran before it: `grep -q "placeholder text" file && echo not-filled || commit`. That
  gate is what turned the next failure into a no-op instead of a second bad push.

Cost of not knowing this: seven failed patches and roughly five turns across one session,
plus one bare template pushed to the registry and corrected in a follow-up commit.
