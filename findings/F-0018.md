## Expected vs actual

**Expected:** the compiler's self-link handling was fixed after adversarial finding
20 (ambiguous paths refused; via= honoured). The curated free-form gate (n=24)
was green.

**Actual:** the generated bench - cases derived from every verified link in three
AdventureWorks databases - failed 11 of its first 438 cases, all self-joins
(DimAccount -> parent account, DimEmployee -> manager). The compiler's
fact-attribute shortcut fired even when via= named the parent link, so "SUM by
manager's title" came back grouped by the employee's own title. A valid query
about the wrong person. Finding 20 had two halves; one was fixed.

## Reproduction

```
python scripts/ontology_bench.py --database AdventureWorksDW2025   # before f49f34d
  SUM(dbo.DimAccount.AccountCodeAlternateKey) by dbo.DimAccount.AccountType:
  group sets differ: compiled-only [('Flow',), ('Balances',)], oracle-only []
```

## Root cause class

Coverage by curation. A hand-written case set contains the shapes its author
thought of; a self-join was not one of them. Generating cases from the data's own
declarations reaches the shapes nobody thought of, and reaches n where R-0010
says something (431 cases -> error bound ~0.70 pct, versus ~12 pct at n=24).

## Invariant gap

R-0010 is satisfied by the bench and not by the curated gate; the gap is that
nothing required an n-large measurement before an accuracy claim was written
into a decision record. Proposed rule: an accuracy claim in a DR cites the n it
was measured at and the bound R-0010 gives for that n.

## Notes

Stated honestly in the bench output: it bounds the deterministic engine layer
only. Natural-language understanding is still measured at n=24. The two bounds
multiply; neither substitutes for the other.
