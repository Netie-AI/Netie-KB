## Expected vs actual

**Expected:** SQLSRC-06 / EPIC-020: after a pull with `max_rows` below the parent row
count, `verify()` says something about a child whose parent was capped. The ticket
says if it says nothing, that is a finding, not a pass.

**Actual:** On Docker SQL Server 2022 (`sqlsrc06-mssql`), `customers` 1100 rows,
`orders` 160 (80 early PK + 80 pointing at C1021-C1100). Pull at `max_rows=1000`
landed 1000 customers (truncated), 160 orders (not truncated). 80 orders had no
landed parent. `Ontology.verify()` returned `[]`. The declared
`FK_Orders_Customers` was stored as `many_to_one` / `max_fanout=1`.
`compile(revenue, group_by=customers.region)` returned a `CompiledQuery` with a
LEFT JOIN and the note "verified many-to-one, so no fact row is duplicated".
True SUM(amount) on landed orders = 2400; INNER JOIN to landed customers = 800.
The cap invented orphans; the compiler treated the join as safe.

## Reproduction

Seed SQL Server `sales.dbo.customers` with 1100 PK rows C0001-C1100, `orders` with
80 rows on C0001-C0080 and 80 on C1021-C1100. Reader login SELECT only.

```
extract = ingest_source_database(cfg, tables=["customers","orders","items","secrets"], max_rows=1000)
onto = from_manifest(extract.manifest_entry, relation_for=...)
onto.add_measure("revenue", "dbo.orders", "SUM(TRY_CAST(f.amount AS DOUBLE))")
violations = onto.verify(con)   # []
got = onto.compile("revenue", group_by=[("dbo.customers", "region")])  # CompiledQuery, not Refusal
```

Orphan count: `SELECT COUNT(*) FROM bronze.dbo_orders o WHERE NOT EXISTS (SELECT 1 FROM bronze.dbo_customers c WHERE c.cust_ref = o.cust_ref)` -> 80.

## Root cause class

**Cardinality measured on the landed parent only.** `verify()` checks parent-side
uniqueness and nullness. It does not ask whether every child key still exists in the
parent after the pull. A `max_rows` cap is a second writer of the join shape: it can
invent orphans the source never had. Uniqueness of the remaining parent keys is
necessary and not sufficient.

The unit fake never built this shape. SQL Server cannot declare the lying FK the
fixture uses; the live-only class is the capped parent. Fakes hid it.

## Invariant gap

Missing rule: **a capped extract is not a complete parent for any declared FK.**
`truncated=true` on a parent must either (a) keep every link to that parent
`unverified` / refuse compile through it, or (b) report orphan counts as
violations. R-0001 on the receipt (`truncated: true`) held; the compiler still
answered. R-0011 silent degradation of the join.
