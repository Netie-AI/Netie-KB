## Expected vs actual

**Expected:** Playwright MCP types into a form using a live snapshot ref, and UACC types the same string into an OS field, both accurate, without the laptop stalling.

**Actual:** UACC `get_system_info` showed 96.2 percent RAM (0.5 GB free). First JPEG screenshot worked. Follow-up UACC calls timed out. Playwright default snapshots go stale under that lag, so `[ref=]` signatures disappear and clicks/types miss. UACC `type_text(human_like=false)` still runs human-mimicry per-char pyautogui because `UACC_HUMAN_MIMICRY` defaults true and the tool only ORs mimicry on, never off. ASCII does not take the clipboard path; keys drop.

A UACC screenshot without `overlay=markers` also has no Set-of-Mark signatures.

## Reproduction

1. `CallMcpTool` UACC `get_system_info` while Cursor + Claude + Chrome + Grok Bot are open.
2. UACC `screenshot` full PNG (no save_path) then `uacc_query(mode=full)` -- MCP timeout.
3. Playwright `browser_snapshot`, wait, then `browser_type` with the old `target` -- ref gone or fill misses React.
4. UACC `type_text` with default env -- dropped/wrong characters under CPU load.

Light path that worked this tick: JPEG region screenshot with `save_path` (640x400, quality 50) returned in one call, no inline image.

## Root cause class

**The handle the agent acts on is an intermediate artifact (snapshot ref / per-char key events), not the field value the operator sees.**

R-0001: asserting "tool returned success" is not asserting the text in the input. Playwright `fill()` success and UACC `characters_typed: N` can both be true while the box is wrong or empty.

## Invariant gap

Missing rule for computer-use: **re-acquire the signature immediately before the write, and write by clipboard/fill-verify, not by unattended keystream.** R-0001 is the closest; it does not yet name MCP refs or SoM badges.
