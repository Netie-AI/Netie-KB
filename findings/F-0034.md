## Expected vs actual

**Expected:** Crew GET `/crew/health`, `/crew/belt`, and `/v1/belt` return inside Control's 1.5s probe. An unreachable Cortex engine is a named `engine.ok=false`, never a hang that looks like Crew itself is down.

**Actual:** `EngineBridge.health()` used a 5s httpx timeout and `/crew/health` awaited it sequentially with OpenVault `healthz` (1.5s). Control's dual belt probe then timed out. Live `:8020` is still the Cortex-crew fork (health hang + `/crew/belt` 404), so the operator still sees unread until YOU step 8 rebind.

**What held:** Control still 405s `/v1/run` `/v1/goal` `/v1/route` `/v1/secrets`. Agents do not restart `:8020` (R-0015).

## Reproduction

1. Point Crew `bridge.health` at a hang (or leave live fork on `:8020`).
2. GET Control `http://127.0.0.1:8040/v1/belt` with 1.5s timeout.
3. On engine tree after the fix: Crew returns JSON in ~1s with `engine.ok=false`. On the live fork: timeout / 404 remains until founder rebind.

## Root cause class

Peer probe waited on the slowest dependency instead of fail-closing for the display client.

## Invariant gap

R-0011 (unknown never green / stated absence) did not cap the Crew-side wait, so Control could not name the absence in time.
