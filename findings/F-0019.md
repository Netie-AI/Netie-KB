## Expected vs actual

**Expected:** a fix applied to the working tree and verified green (35 tests, bench
431/431) survives until the author commits it a few minutes later.

**Actual:** between the verification and the commit, another lane committed to
the same file (d334747, itself fixing a real bug of the author's - functions
appended after the `if __name__` guard). The author's uncommitted hunk in that
file was gone, and the untracked bench script vanished with a worktree switch
(.worktrees/pr61, pr64, pr65 appeared). The bench had to be recreated from the
conversation and the fix re-applied. A test someone had written for the fix was
sitting uncommitted in the tree, failing, with no fix under it.

## Reproduction

Two lanes on one branch, one with uncommitted edits to scripts/ontology.py, the
other committing a change to the same file and switching worktrees. Observe with
`git status --short` before and after.

## Root cause class

Treating "verified in the tree" as "done". R-0008 says uncommitted work does not
exist; the lane rule R-0006 says several lanes work these repos at once. Together
they mean the window between green and committed is the window in which work is
lost, and it was.

## Invariant gap

R-0008 covers it. The gap is cadence: commit immediately after the verification
that makes a change committable, not at the end of a stage. Proposed habit: a
passing test run on new files is followed by `git add <paths> && git commit` in
the same command.

## Notes

The lost bench was recoverable only because its full text was in the session
transcript. That is luck, not a control.
