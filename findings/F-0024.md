## Expected vs actual

Expected: 6 open PRs each needing its own CI fix before merge (per-PR archaeology).
Actual: one integration branch (demo/rag-cross-compare, PR #12, already green)
CONTAINED three of the other PRs' full content plus 3 commits that local master
showed as "ahead 3" unpushed. One merge closed #12, auto-marked #2 merged,
emptied #5, and erased the local-master divergence. Only 2 PRs held real work
(a conflicted stacked branch and a rebase-needed branch). The Kilo Code Review
check showing "fail" on every PR was a billing notice ("account out of credits"),
not code findings - zero review comments existed on any PR.

## Reproduction

1. git fetch --all --prune
2. Containment proofs before any merge/delete decision:
   - git branch -r --merged origin/<integration-branch>
   - git merge-base --is-ancestor <tip> origin/master
   - git cherry origin/<branch> master  (empty output = all patch-equivalent)
3. Free containment proof from GitHub: gh pr edit N --base master refusing with
   "no new commits between base and head" proves the PR is fully contained.
4. Merge the integration PR with a MERGE COMMIT (not squash) so sub-branch SHAs
   become reachable and GitHub auto-marks contained PRs as merged.
5. Retarget stacked PRs (gh pr edit N --base master) BEFORE deleting their old
   base branch - deleting a base branch directly closes its PRs.
6. Delete only branches that pass step 2; superseded-not-contained branches stay
   recoverable via their closed PR ref (refs/pull/N/head).

## Root cause class

Bookkeeping divergence, not code divergence: refs (local master, PR base refs,
stale branches) pointing at content that already traveled to master through a
different ref path. The fix class is "prove containment, then collapse refs",
never "re-fix or re-merge the content". Second class: an external required-looking
check (Kilo) failing for a reason unrelated to the code (billing) - reads as CI
debt but is vendor state.

## Invariant gap

- R-0008 held in spirit but its check is one-sided: "unpushed work does not
  exist" - here the unpushed commits DID exist remotely under another ref.
  git cherry is the disambiguator before panicking about "ahead N".
- R-0011 (a silent fallback is a lie): Kilo red-on-every-PR was a billing state
  masquerading as review findings. A check that cannot run must say so in the
  check name/status, not fail identically to a real finding. Named in AirGPT
  CHANGELOG 2026-08-25 so the red check is not read as code quality.
- Windows lane hazard (known #28 class in AirGPT): pytest can print its summary
  and then hang alive on a locked sqlite handle, wedging worktree removal and
  stalling background-shell lanes that wait on their own zombie. Kill the
  reported-done pytest PID before removing its worktree.
