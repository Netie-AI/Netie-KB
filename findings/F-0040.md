## Expected vs actual

**Expected:** GET `/crew/health` probes OpenVault once (PEER_HEALTH_WAIT_S 1s) in parallel with the engine ping. Provider chain listing is env/config, not a live vault probe. Inspector engine unread is a failed GET, not a stacked hang.

**Actual:** Disk `resolve_providers` no longer calls `healthz`. Live `:8020` is still the Cortex-crew fork. Agents must not restart it (R-0015).

**What held:** Control still 405s `/v1/run` `/v1/goal` `/v1/route` `/v1/secrets`. Converse stays `:8020`.

## Reproduction

1. `test_resolve_providers_does_not_ping_openvault` asserts healthz is not called.
2. `test_health_pings_openvault_once` sleeps 0.35s in healthz and asserts n==1 and wall clock `< 0.6`.
3. `GH_WAIT_S` is 1.5. IMAP SSL timeout is 1.5.

## Root cause class

Two independent live probes of the same peer on one request.

## Invariant gap

R-0011. Hung OpenVault made the engine chip look unread.

## Notes

GET `/providers` still may call `vaulted_provider_ids` (1.2s, cached 60s). That is under the 2.5s UI cap.
