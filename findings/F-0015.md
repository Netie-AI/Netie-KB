## Expected vs actual

Expected: `python scripts/ontology.py --adventureworks` derives and verifies
ontologies over the extracted lake. Actual: NameError at the call site in
main() - `run_adventureworks` did not exist yet, because `cat >>` had appended
it (and `from_manifest`) AFTER the `if __name__ == "__main__"` block. 34 tests
passed the whole time.

## Reproduction

1. Module with `if __name__: main()` guard mid-file, definitions appended below.
2. `import module` - fine: the whole file executes top to bottom, all defs bind.
3. `python module.py` - main() runs at the guard line, before the later defs
   exist. NameError.

## Root cause class

Import-time vs execution-time coverage split. Tests import the module, so the
test suite exercises a different execution order than the CLI does. Same class
as the d_Sales.Customers alias defect in the same file: isinstance-only
assertions certify an artifact nobody ever executed. The append tool
(`cat >>`) is incidental; any edit that grows a file below its entry point has
this shape.

## Invariant gap

R-0001 - the gate must assert the artifact the customer receives, at the layer
they receive it from. The CLI IS a delivery layer, and no test ran it. A
subprocess smoke test (`python scripts/x.py --help` exits 0) per script would
have caught both this and nothing else being needed. R-0007 also applies: the
CLI path was trusted green without ever having been shown able to run.

## Notes

Fixed in dms d334747 by moving the guard to end-of-file. The rendered lesson:
every appendable script keeps its `__main__` guard as the physically last
statement, and each scripts/*.py gets one subprocess invocation somewhere in
the suite.
