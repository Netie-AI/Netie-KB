## Expected vs actual

**Expected:** Pointer writes every consequential action to a tamper-evident ledger, so
"what did it click" has an answer. `ecosystem.js` says so in its own header: "Every action
Clicks takes is written to the Cortex audit ledger."

**Actual:** `audit()` was a single POST to Cortex `/dms/audit/append` wrapped in a bare
`catch { return false }`. Cortex on this laptop is usually not running. So the normal case
was: nothing written anywhere, no local copy, no queue, no retry, and a return value the
call sites ignore. Nine call sites across `main.js` all looked like they were auditing.
None of them were.

The comment on the catch made it sound handled - "the ledger is a safety net, not a gate -
an audit outage must not stop the user's action. Losses are visible via /verify". Both
halves are true and neither is the problem: not blocking IS correct, and `/verify` is on
the Cortex that is down.

## Reproduction

1. Stop Cortex, or just do not start it - the default on this box.
2. Run any Pointer act path that calls `eco.audit`, e.g. a blocked plan
   (`clicks.blocked`) or an executed step (`clicks.action.executed`).
3. Look for the record anywhere on disk. There is none.
4. `await eco.audit(...)` returns `false`, which no caller checks.

## Root cause class

**A remote best-effort write standing in for the durable record.** The failure mode is not
"the network call failed" - that was handled. It is that the only copy of the data was the
one being sent, so durability and replication were the same operation and losing the second
lost the first.

The tell is generic and worth grepping for: a function whose whole body is a remote call in
a try/catch, whose name is a noun the product promises (audit, log, record, receipt,
history), and whose failure path returns a value callers discard.

## Invariant gap

`R-0011` (a silent fallback is a lie) is the closest and does not quite reach it. R-0011 is
about degradation being visible *in the output*; here there was no degraded output to look
at, because the degraded mode produced no artifact at all. The missing half:

> The durable copy is written locally FIRST; sending it anywhere is a second,
> separately-failing step. A component that cannot say whether it recorded something is
> not recording.

`F-0030` (one vault, one orchestrator) is why the fix is a local ledger that syncs to
Cortex rather than a second audit service. Local-first is not a second source of truth: the
chain shape matches the Cortex ledger so the two can be compared.

## Notes

- Fix: `electron/netie/ledger.js` - append-only NDJSON, hash-chained, daily rotation, sync
  watermark in a sidecar so the log itself is never rewritten. `audit()` appends locally,
  then posts, then advances the watermark only on a Cortex 200.
- `auditHealth()` returns `{local, pending, chainOk}` and reports `local:false` with a
  reason when no ledger is attached. "0 pending" must never be how a UI renders "nothing is
  being recorded".
- Secret values never enter the ledger: keys match by shape (`user_password`,
  `Authorization`, `card_number`) rather than exact spelling, and a custody action's value
  is blanked a second time at write. `passport_name` stays fillable - the same trap
  `A-0006` documents for the custody word list.
- Same-session build that depends on this: `electron/netie/mandate.js`, the
  pre-authorisation that makes unattended execution possible without reopening `A-0005`.
  Authority is held by the runner, never carried on the action; an action arriving with
  `_approved` or `_mandateId` is refused as tampering.
- Bug the mandate tests caught, same class as any falsy guard: `if (m.revokedAt)` reads
  timestamp `0` as "never revoked", so under an injected clock a revoked mandate kept
  authorising steps. Use `!= null` for every timestamp guard.
