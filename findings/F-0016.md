## Expected vs actual

**Expected:** Cursor connects Pointer HUD, Cortex plans via `/dms/agents/computer-use`, UACC is the only OS mouse, Playwright types into DOM with live `[ref=]` plus `[box=]`.

**Actual:** Pointer `NetieEcosystem.secure()` against live Cortex `:8010` returned `blocked=false`, `degraded=false`, `cortexOnline=true`. `planViaCortex()` failed `cortex /dms/agents/computer-use 404`. OpenVault `:5000` was down. Pointer Electron was not running. NetieSpace.exe pid 30380 had no visible window (1x1 GDI+ only). RAM 95.2 percent (0.7 GB free) -- booting Pointer HUD would be a second lag source. Pointer `driver.js` SendInput is a second mouse if it runs beside UACC.

Playwright still typed `pointer-probe-ok` into a data-URL field and kept `[ref=f1e2] [box=95,8,170,21]`. UACC `overlay=markers` plus JPEG failed (`cannot write mode RGBA as JPEG`); PNG `save_path` succeeded.

## Reproduction

1. `POST http://127.0.0.1:8010/dms/secure` with Bearer `dms-demo-steward-key` -- 200, not blocked.
2. `POST http://127.0.0.1:8010/dms/agents/computer-use` -- 404.
3. `node -e` requiring `D:\Pointer\electron\netie\ecosystem.js` `planViaCortex` -- same 404.
4. `list_windows` -- no Pointer HUD. NetieSpace hidden.
5. UACC `screenshot(overlay=markers, image_format=JPEG)` -- OSError RGBA.

## Root cause class

**Three control planes were treated as one product, but only the gate is live.** Cortex `/dms/secure` is real. The computer-use planner is a documented swap point (`ecosystem.planViaCortex`) with no route on this engine. The OS mouse already exists (UACC). Pointer HUD/driver is a third executor. Wiring them as one "Pointer control" without a split makes lag, missing signatures, and a second SendInput stack.

R-0011: `NETIE_CU_PLANNER=1` would silently fall back to OpenVault LLM. OpenVault was down, so the fallback would also fail -- that failure is honest. A 404 plus silent OpenVault plan would be the lie.

## Invariant gap

Missing computer-use split rule: **Pointer HUD + Cortex `/dms/secure` confirm; UACC clicks; Playwright DOM; Pointer `driver.js` stays dry-run when UACC is the mouse.** P-05 (Pointer as loopback MCP actuator) stays parked. C25-01 is claimed in Pointer `docs/ACTIVE_PLAN.md` as scaffolded in `sidecar_routes.py`; this Cortex tree has no such route.
