## Expected vs actual

**Expected:** R-0016 says one registry and no lane keeps a private skills folder, so a
skill name resolves to one document.

**Actual:** six names resolve to two documents each, with different content, in two
formats, for two different agent tools - and nothing marks either as the source.

Measured on `D:\Cortex` at `claude/crew-agentic-interface`, 2026-08-25:

| skill | `crew/skill_packs/<n>.md` | `.cursor/skills/<n>/SKILL.md` | identical |
|---|---|---|---|
| chat-human | 21 lines | 47 lines | no |
| computer-reach | 22 | 35 | no |
| feedback-learn | 17 | 58 | no |
| proposal-artifact | 14 | 46 | no |
| skill-route | 16 | 49 | no |
| voice-learn | 25 | 39 | no |

`cmp -s` returns non-zero on all six. The Cursor copies run two to three times longer,
which suggests they were extended after the fork rather than being a stale export.

So a Crew agent and a Cursor agent asked to follow "the `feedback-learn` skill" receive
materially different instructions, and neither can tell that the other exists.

## Reproduction

```
cd D:\Cortex
for s in chat-human computer-reach feedback-learn proposal-artifact skill-route voice-learn; do
  a="CortexOS/crew/skill_packs/$s.md"; b=".cursor/skills/$s/SKILL.md"
  echo "$s pack=$(wc -l < "$a") cursor=$(wc -l < "$b") identical=$(cmp -s "$a" "$b" && echo YES || echo NO)"
done
```

## Root cause class

**A document with two consumers and no generator will fork.** Not "someone forgot to
sync" - that framing invites a sync script and the fork returns. Two tools needed the
same instruction in two formats, both formats were hand-authored, and hand-authored
copies of one truth diverge by default. R-0009 already names the shape: an artifact with
more than one required representation is a generated artifact, and hand-authoring it is
the defect.

The same class explains why the estate has four skill directories at all: each new agent
surface hand-rolled its own rather than rendering from the registry.

## Invariant gap

R-0016 exists and is violated. What is missing is enforcement: nothing detects two files
claiming the same skill name, and nothing marks a source.

Candidate: a check that every name under `.cursor/skills/` and `crew/skill_packs/` maps
to exactly one registry `S-####`, and that the runtime copies are byte-identical to what
the registry renders. That check fails today on six names, which is the point - it should
be written so it goes red, then the six resolved, rather than written to pass.

## Notes

**Do not resolve this by deleting one side.** Both are loaded by their tool at runtime -
`board.py:68` and `server.py:85` read `skill_packs`; Cursor reads `.cursor/skills`. The
resolution is to pick the authoritative content per skill, put it in the registry, and
generate both representations from it.

Picking which content wins is judgement per skill and cannot be automated: the longer
Cursor copies may be improvements worth keeping, or may be drift. Six decisions, one per
skill, and they belong to whoever wrote them.

**Not attempted here.** These files were live in another lane's working tree at the time
of the audit (27 uncommitted files on the same branch), so editing them would have raced
an active writer - the exact collision class as F-0025.
