## Trigger

Any wire-visible change to `packages/cortex_contract/` or OpenAPI surface.

## Shape

Single lane, sequential: classify change → bump version → regenerate spec → compat check → test vectors → DMS pin notice.

## Rationale

Contract majors strand consumers; minors must be additive. Hand-editing `contract/*.json` created shadow specs (R-0009).
`canonical_manifest_bytes()` changes are majors requiring coordinated DMS release.

## Steps

1. Classify: additive (minor) vs breaking (major).
2. Bump `version.py` AND `pyproject.toml` in same commit.
3. `python scripts/export_openapi.py` — never hand-edit JSON.
4. `python scripts/export_openapi.py --check` in CI.
5. Update `contract/compat.yaml` if serving multiple majors.
6. Regenerate `contract/testvectors/` if canonicalisation touched.
7. File handoff for DMS to pin new `cortex-contract`.

## Anti-patterns

- Patch bump for field removal (must be major).
- Regenerate spec in a follow-up commit (drift window).
- Delete old published OpenAPI files.

## Model tier

| Step | Tier | Why |
|------|------|-----|
| Classify + bump | large | breaking vs additive judgment |
| Regenerate + check | small | mechanical |
| Handoff write | small | template |

## Cost

1–2 hours for minor; half-day+ for major with DMS coordination.

## Proven on

contract 1.0.0 → 1.1.0 → 1.2.0 (2026-06 through 2026-07).
