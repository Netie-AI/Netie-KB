## When to use

At the start of any working session, and before seating yourself on any repo,
branch, ticket, or machine resource another lane might hold.

## Steps

1. Presence first: read `D:\Netie\Internal\Agents\RUNTIME.md` (regenerated every
   15 min by the estate watchdog). It lists live services, live Claude pads,
   open PRs with writer guesses, and who does what this tick. Remote agents
   follow W-0005 instead.
2. Locks second: read `D:\Netie\Internal\Agents\CLAIMS.json` then `FLEET.md`.
   One writer per branch. HELD / EXTRA_STOP / BRANCH_HOLD means pick a different
   ticket, not a second seat.
3. Health third: `GET http://127.0.0.1:8020/crew/health` shows the OpenVault
   mesh, active provider, grok_offloaded, and which computer-control MCPs are
   armed.
4. Queue, do not grab: a request for another lane becomes a GitHub Issue
   (the SoT) or a crew send_message - never a silent takeover of their branch
   or session.
5. Intermediary needs (a judgement, a verify, a second opinion) go to a NEW
   chat, pad, or API call - never hijack a session that is mid-work.
6. Help by distilling: when you learn something another lane will need, file it
   in the KB (`kb.py new finding|skill`) and push - that is how lanes help each
   other without interfering (R-0016).

## Verify

Before writing: name the lane that holds your target branch (from RUNTIME.md +
CLAIMS.json) or state "unclaimed". If you cannot name it, steps 1-2 were not
done.

## Do not

Do not rewrite commits you did not author (R-0006). Do not close or launch the
founder's software to free a resource (R-0015). Do not invent a fourth
orchestrator - RUNTIME.md + Plane + GitHub Issues are the loop.
