## When to use

Before authoring, planning, or re-deriving anything an agent anywhere in the
estate may have solved before - and after finishing work that taught you
something reusable.

## Steps

1. Pull (pick the nearest surface):
   - This laptop, any shell: `python D:\Netie-KB\scripts\kb.py search "<kw>"`
   - Claude Code session, any repo: MCP tools `kb_search` then `kb_show <ID>`
     (server name `netie-kb`, registered at user scope).
   - Container or other machine with git: clone
     `https://github.com/Netie-AI/Netie-KB`, then run kb.py or
     `scripts/skill_server.py` locally.
   - Container without git: REST `GET <server>/search?q=` and
     `GET <server>/item/<ID>` (bearer token required off-loopback).
2. Use: `kb_show` the artifact and follow its Steps/Check verbatim before
   improvising. A workflow on the shelf outranks a fresh derivation.
3. Improve: when reality diverged from the artifact, file a finding
   (`kb.py new finding`) naming expected vs actual; promote survivors with
   `kb.py promote F-#### --to rule|workflow`. New reusable methods become
   `kb.py new skill`.
4. Push: `git add <exact paths>; git commit; git push` (R-0006, R-0008). The
   estate watchdog pulls the KB on the founder laptop every 15 min, and the
   server reads the corpus per request - a pushed skill is served with no
   restart.

## Verify

Your new artifact appears in `kb_search` output from a DIFFERENT surface than
the one you authored on (for example: authored via kb.py, found via the MCP
tool).

## Do not

Do not keep a private skills folder per lane or per repo (R-0016). Do not
hand-edit rendered packs - edit the corpus and run
`python D:\Netie-KB\scripts\sync_agents.py --force` (R-0009).
