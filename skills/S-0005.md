## When to use

You are the seated writer for one named GitHub ticket (or one context-sized
batch that shares a mental model). The Ticket Runner *manager* seats you; this
skill is the copy-paste for the writer. Also use it when the founder pastes a
long "You are the Ticket Runner for X" block.

## Steps

1. Read the repo `CLAUDE.md` hard rules, `STATUS.md`, `docs/ACTIVE.md`, then
   `gh issue view <N>` and the parent epic. Follow that ticket's Agent prompt
   exactly. Do not widen.
2. Hygiene: `git status --short`. Ignore named noise (`.venv_audit/`). Leave
   unrelated stashes. If anything else is dirty, STOP (R-0008). Do not build on
   a stale `cursor/*` branch. `git fetch origin` then
   `git worktree add -b feat/<key> <ABS>-wt-<key> origin/main` (WSL path
   `/mnt/<drive>/...`). One writer per branch. Claim the ticket first
   (F-0019, F-0025, S-0001).
3. Reuse what exists. Name the functions/ports/fixtures. YAGNI. If the work
   looks like it violates a hard rule, state the distinction or STOP.
4. If two semantics conflict and the ticket did not settle it, implement the
   unambiguous part and report the conflict. Do not invent a resolution.
5. Gate (R-0007): fixture built in-repo, never skip (R-0002). Missing dep =
   FAIL with the cause named. Stash the implementation, run the gate, confirm
   FAIL; unstash, confirm PASS. Quote both. Assert the customer artifact
   (R-0001).
6. Run the repo's own test command (CLAUDE.md / README / pyproject /
   `scripts/ci_local.sh`). Full suite too. If a DB or service is down, say so
 - do not fake a pass.
7. Commit on the feature branch. Do not push / PR / merge / touch main unless
   the founder said so. Message names `repo#N` / parent epic, states hard-rule
   reasoning, names what the ticket still does NOT do.

## Verify

The report names: files + line counts, migration name if any, FAIL output,
PASS output, full-suite result, commit sha, leftover blockers. A gate that
passed before the fix proves nothing.

## Do not

Do not spawn one agent per open issue. Do not attach a second writer to a
held branch. Do not skip, xfail, or delete a deliberately red gate. Do not
close from the implementer run (R-0003 - different-run verify first). Do not
drive an external product the ticket listed as out of scope.
