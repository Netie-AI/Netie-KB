## When to use

Any agent that must operate this Windows laptop's browser or OS surface
(screenshots, clicks, typing) - only while laptop-operating is sanctioned and
armed, and only on apps the founder opened voluntarily (R-0015).

## Steps

1. Route by surface: web pages -> Playwright MCP; OS surface -> UACC. Never a
   second OS-mouse stack next to UACC (no windows-mcp, no computer-control-mcp).
2. Arming: computer control is OFF by default. Crew /crew/health lists uacc,
   windows-mcp, computer-control-mcp as "off (CORTEX_COMPUTER_CONTROL not
   set)". Arm only via the sanctioned path (Cursor MCP reload +
   CORTEX_COMPUTER_CONTROL=1 on Crew, per MCP_LAZY.md) - never by installing
   another MCP.
3. Playwright settings that survive lag: config
   `D:\Netie\Internal\Agents\playwright-mcp.config.json`, imageResponses=omit,
   snapshot boxes on, settle 200ms, type slowly on React inputs.
4. Playwright refs are snapshot-scoped signatures: after navigate/wait/lag,
   re-snapshot before acting - a stale `[ref=eN]` is a dead handle.
5. UACC typing under load: human_mimicry off via the call arg is NOT honored
   (env default wins) - use clipboard_write + ctrl+v for accurate text entry.
6. UACC screenshots: jpeg region or overlay="markers". A bare full-PNG
   screenshot has no signatures and can blow the MCP timeout.

## Verify

A login-form fill via Playwright lands the exact text after an MCP reload; a
UACC jpeg screenshot returns inside the MCP timeout. If either fails, check
RAM first - this laptop sits near 96 percent and heavy tools time out before
they error.

## Do not

Do not run uacc_query(full) or OCR-heavy modes under load. Do not type
character-wise under CPU load - keys drop. Do not add Windows-MCP (GROK_SYNC
forbids a second PyAutoGUI stack). Do not drive apps the founder did not open.
