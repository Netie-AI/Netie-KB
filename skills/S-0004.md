## When to use

Before authoring a skill, and any time you search for one. R-0016 says search the
registry first - this entry tells you what the registry does and does not cover, so
"no hits" can be read correctly.

## Steps

**1. Search the registry.**

```
python D:\Netie-KB\scripts\kb.py search "<keywords>"
```

Or the MCP tools `kb_search` / `kb_show` / `kb_list`. The server answers on
`127.0.0.1:8030` and `netie-kb` is already registered in `.claude.json`.

**2. Know that the registry is not the whole estate.** Four locations hold
skill-shaped files and they are **not four copies of one thing**. Three are loaded by
running code and cannot be moved without breaking it.

| Location | Count | Consumed by | Movable |
|---|---|---|---|
| `D:\Netie-KB\skills\S-####.md` | 4 | agents, via kb.py and MCP | this IS the registry |
| `D:\Cortex\skills\*.yaml` | 15 | engine code - `CortexOS/discovery/catalog.py:70` `load_skill_cards()`, `hls_compiler.py` via `SkillMesh` | no - breaks skill discovery |
| `D:\Cortex\CortexOS\crew\skill_packs\*.md` | 11 | crew server - `board.py:68 PACKS_DIR`, `server.py:85 ensure_skill_packs()` | no - breaks the crew server |
| `.cursor/skills/<name>/SKILL.md` | 10 | Cursor agents | yes, but see Do not |
| `~/.claude/skills/<name>/` | 5 | Claude Code, this machine only | yes |

**3. If the registry returns nothing, grep the runtime directories** before concluding
the skill does not exist. A skill the engine loads is a capability definition, not an
instruction to you, so it is usually not what you want - but knowing it exists stops
you re-deriving it.

**4. Read "no hits" correctly.** 4 of roughly 44 skill-shaped files in this estate are
registry entries. Absence of a hit is weak evidence of absence.

## Verify

You have used this skill correctly when, having found nothing in the registry, you can
state which of the runtime directories you also checked. A search that consulted only
`kb.py` and concluded "nothing exists" has checked under 10 percent of the estate.

## Do not

**Do not "fix" the scatter by moving files.** Two of the four directories are read by
code at import time; moving them breaks the engine's skill discovery and the crew
server. The correct repair is to make the registry the authoritative source and
generate the runtime copies from it (R-0009 - never hand-author a generated artifact).
Nobody has built that yet.

**Do not cite any of these six without naming which copy you read.** They exist in both
`crew/skill_packs` and `.cursor/skills`, with different content and no marker saying
which wins:

`chat-human` `computer-reach` `feedback-learn` `proposal-artifact` `skill-route`
`voice-learn`

Measured 2026-08-25: none is identical to its twin, and the Cursor copies run two to
three times longer - `feedback-learn` is 17 lines against 58. Two agents can follow
"the same skill" and receive materially different instructions. See F-0026.
