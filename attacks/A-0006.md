## Attack

`resolveVaultTemplates` blanks secret values and sets `_custody` / `disposition:"custody"`.
`reviewPlan` then rebuilds `safety` via `decide()`, which used to trust only the on-screen
label heuristic (`SECRET_TARGET_WORDS`). Labels like "Recovery words" or "Code" miss the
list -> disposition downgraded to `approve` -> OpenVault never called -> driver types `""`
and reports `{ok:true, typed:0}`.

## Fix

`decide()` treats `action._custody` as authoritative secrecy. The text heuristic may only
**add** secrecy, never remove it.

## Reuse

Any pipeline that stamps a security disposition early, then re-derives it later from
redacted or blanked data, will silently lose the stronger disposition. Preserve an
explicit sticky flag (`_custody`, `_refuse`, ...) across re-annotation.

## Fixture rule (R-TEST-MECH)

Do not test custody with `target: "Password"`  -  the word-list heuristic catches that
alone and the test stays green while the sticky flag is broken.
