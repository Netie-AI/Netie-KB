## The attack

Any ingest that derives a storage name by sanitising a source name - replacing
non-alphanumerics with `_`, lowercasing, truncating to N characters - has collapsed a
many-to-one map onto its key. Two source tables whose names differ only in a character
the sanitiser erases, or only past its length cut, resolve to the same target. The second
write replaces the first.

Shapes that collide under a typical `alnum -> _`, `lower()`, `[:60]` sanitiser:

| source A | source B | both become |
|---|---|---|
| `dbo.a-b` | `dbo.a_b` | `dbo_a_b` |
| `dbo.Sales` | `dbo.sales` | `dbo_sales` |
| `dbo.x y` | `dbo.x.y` | `dbo_x_y` |
| any 61+ char name | same first 60 chars | identical |

The damage is not the collision. It is that the **receipt says both landed.** In the
measured case `SourceExtract.pulls` reported `('dbo.a-b', 'bronze.dbo_a_b', 2)` and
`('dbo.a_b', 'bronze.dbo_a_b', 1)`, one registry row existed, and the table held one row.
A customer reading the receipt would believe three rows were extracted. Two were destroyed
by a DROP+CREATE that no one asked for.

## Where it applies

Any name-sanitising ingest, file or database. The estate had already met it on files:
`2023/sales.csv` and `2024/sales.csv` both stemmed to `sales`, and a folder upload
destroyed one with the other (`bronze.py`, `_claim_table_name` docstring). The SQL
connector re-introduced the same class on a different input because it wrote its own
`_bronze_name` and skipped the claim the file path already had.

## Detection

Two tests, both cheap:

1. **The collision probe.** Ingest two sources one erased-character apart. Assert two
   distinct targets, both row counts preserved, and a note on the second receipt.
2. **The re-pull probe (R-0005).** Ingest the SAME source twice. Assert one target, no
   suffix, no note - re-ingesting is what a person means by pulling again, and a claim
   that suffixes every second pull is worse than no claim.

## Defence

Claim the name against a registry keyed on the *source identity*, not the sanitised
stem. Same stem held by a **different** source -> suffix with a short digest of the source
identity and report a note; same stem held by the **same** source -> reuse. R-0004: fix the
class once in the claim, and route every deriver through it. The file ingest already had
this in `_claim_table_name`; the fix was to call it, keyed on the credential-free source
string, rather than to write a second one.

## What this does not cover

Sanitisers that are *not* many-to-one - a content-addressed name, or a name that carries a
per-source digest by construction - do not collide and do not need a claim. The attack
applies exactly when a human-readable target name is derived from a source name.
