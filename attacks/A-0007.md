## Attack

The "idiot-proof" recipe fast path (`matchRecipe` -> `reviewPlan` -> `maybeRunPlan`) and
the skills-expanded plan path reached the driver without calling Cortex `/dms/secure`.
When Cortex is down, `planActions` correctly fail-closes  -  but recipes still ran desktop
SOPs (open app, click, type) on ungated user text. That breaks the Act invariant:
**no consequential screen control without a live security gate**.

## Fix

Every recipe and skills act entry calls `eco.secure(message, { failClosed: true })` before
`maybeRunPlan`. On block: refuse, HUD-surface the reason (R-0011), audit
`clicks.blocked` with `where: "recipe"` / `"skills"`.

## Detection

```bash
rg -n "expandRecipe|matchRecipe" electron/main.js
# Every branch that then calls maybeRunPlan or executeApproved must secure first.
```
