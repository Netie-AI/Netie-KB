## Rule

Agents never start, restart, or kill the founder's desktop software. Grok Bot.exe,
Cursor, and every other user-facing app open and close only by the founder's own hand.
Cursor is the founder's primary tool - never close it, not even to free RAM.
When the founder opens an app voluntarily, the crew's job is to observe and distill
(skill_distill captures), not to drive, manage, or relaunch it. Keep-alive automation
covers estate services only (Docker, Plane, Crew, OpenVault); a desktop app is not a
service. If an app is in the way, report it and wait for the founder.

## Why

1. 2026-08-25: founder reports Grok Bot auto-opened again and Cursor was closed
   mid-work, after already saying not to. Cursor was running priority work.
2. The law existed but lived only in GROK_SYNC.md; lanes that never load that file
   were not bound. estate-watchdog.ps1 and night_watch.ps1 audited clean the same
   day ("Does not kill processes", "watchdog will not restart it"), so the violation
   came from a lane acting outside any rendered rule pack.

## Check

Grep estate scripts and agent code for launch/kill primitives aimed at desktop apps:
Start-Process / os.startfile / subprocess / taskkill / Stop-Process with Grok, Cursor,
or other user apps as target, outside the sanctioned service list. RUNTIME.md's
"Grok Bot" line must read manual-or-OFFLOADED, never "started by watchdog".
